# 🎬 ContentGenAutomator Studio: Product Contract

## Product Contract v2

This document defines the formal operational, architectural, and security contract for **ContentGenAutomator Studio**. It specifies the invariants, state machines, and failure boundaries that every client, agent, and adapter must preserve.

---

## 1. Scope & Capabilities

ContentGenAutomator is a full-lifecycle, stateful, multi-agent cinematic production studio for vertical short-form video generation (YouTube Shorts, TikTok, Instagram Reels).

The platform spans from initial prompt generation and multi-agent drafting to video provider synthesis, FFmpeg composition, brand governance, and multi-gate publishing automation:
1. **Multi-Agent Pre-Production:** 7 specialized Google ADK (`google-adk>=2.8.0`) agents execute grounding, continuity locking, scriptwriting, diffusion prompt drafting, and safety auditing.
2. **Video & Narration Production:** Multi-provider video rendering (`runway`, `kling`, `luma`, `mock`) and TTS voiceover generation with checksummed artifact tracking.
3. **Automated AI Governance:** Dual-pass IBM watsonx guardrails, cryptographically signed compliance certificates (HMAC-SHA256), and dynamic SOC2 audit logs.
4. **Publishing Pipeline:** Modular adapters for YouTube Shorts (OAuth2/Direct upload), TikTok, and Instagram Reels with an 8-gate fail-closed verification pipeline.

---

## 2. Allowed Durations & Scene Pacing

Only these values are valid: `10`, `20`, or `30` seconds. These map deterministically to 1, 2, or 3 ten-second scenes:
* `10s` = 1 scene (Hook + Climax)
* `20s` = 2 scenes (Hook ➔ Development & Climax)
* `30s` = 3 scenes (Hook ➔ Narrative Progression ➔ Call to Action)

The backend is authoritative; any other duration value returns a `422 Unprocessable Entity` or `400 Bad Request`.

## 4. Required Prompt Structure

Every user-facing prompt generated by the agent pipeline must contain these sections in order:

1. `FORMAT` — 9:16 vertical, animated, duration.
2. `CONTINUITY LOCK — MUST REMAIN IDENTICAL` — Visual style, seeds, color palette, lighting rules.
3. `SCENE / VISUAL STORY` — Scene narrative action and framing.
4. `CAMERA AND COMPOSITION` — Dynamic camera movement, angles, and lens directives.
5. `NARRATION — EXACT SCRIPT` — Word-budgeted voiceover lines (~2.5 words/sec, strictly ending before 9.0s).
6. `CAPTIONS` — Synchronized subtitle cues.
7. `AUDIO` — Ambient sound design, Foley effects, and musical cues.
8. `SAFETY AND EXCLUSIONS` — Exclusions (no real people, copyrighted characters, logos, or photorealistic humans).
9. `FINAL GENERATION REQUIREMENTS` — Resolution (1080x1920), frame rate (30fps), color space, audio mix.

## 5. Full Project State Machine

```text
CREATED 
  ➔ INPUT_RECEIVED 
  ➔ FACT_CHECKING 
  ➔ STORY_CREATED 
  ➔ SCENES_PLANNED 
  ➔ AWAITING_NEXT 
  ➔ PROMPT_APPROVAL_PENDING 
  ➔ APPROVED 
  ➔ PRODUCTION_SUBMITTED 
  ➔ CLIPS_RENDERED 
  ➔ VIDEO_APPROVED 
  ➔ PUBLISHING_PENDING 
  ➔ PUBLISHED
```

### State Machine Invariants:
1. **Scene Ordering:** Prompt 1 is generated after scenes are planned. Scene $N$ cannot be generated until Scene $N-1$ is approved.
2. **Optimistic Concurrency Control (OCC):** Mutating requests (`/prompts/{index}/approve`, `/prompts/{index}/regenerate`) require the `X-Expected-Version` header matching the current project version. Omission yields `428 Precondition Required`; version mismatch yields `409 Conflict`.
3. **Idempotency:** Repeated identical requests with matching `Idempotency-Key` return identical responses without duplicate side effects.

## 6. Security, BYOK & FinOps Governance

1. **Bring Your Own Key (BYOK) Vaulting:**
   * Client-side keys (`X-Gemini-API-Key`, `X-Runway-API-Key`, etc.) are passed via request headers and never stored on disk or echoed in API responses.
   * Concurrency is bounded by an admission limiter (max 3 concurrent jobs per key; excess requests receive `429 Too Many Requests`).
   * `/api/byok/verify` is rate-limited via a sliding-window limiter (10 requests/min).
2. **FinOps Token Ceilings:**
   * Each project has a strict ceiling of **50,000 tokens**.
   * When exceeded, requests are halted with `429 Cost Ceiling Exceeded`.
3. **Compliance & Audit Trails:**
   * Compliance certificates are issued only for completed, auditable projects (`422 NOT_YET_AUDITABLE` otherwise).
   * Certificates are signed with HMAC-SHA256 and include cryptographic checksums of prompts and policies.
   * Dynamic SOC2 audit logs record immutable chronological lifecycle events (`PROJECT_CREATED`, `PROMPT_GENERATED`, `PROMPT_APPROVED`, `VIDEO_RENDERED`, `PUBLISH_TRIGGERED`).

## 7. Publishing Pipeline: 8 Fail-Closed Gates

Before any media is delivered to external platforms, all 8 gates must pass:

| Gate | Validation Target | Failure Action |
|:---|:---|:---|
| **Gate 1** | Prompt Approval Status | Block: All scenes must be approved |
| **Gate 2** | Production Job Status | Block: All clips must be successfully rendered |
| **Gate 3** | Human Clip Review | Block: All clips must pass human video inspection |
| **Gate 4** | Fact Verification | Block: Zero unverified or contradicted claims |
| **Gate 5** | Export Manifest & Checksum | Block: Valid, non-expired manifest with matching SHA256 |
| **Gate 6** | Final Director Review | Block: Explicit human sign-off immediately prior to publish |
| **Gate 7** | Concurrency / Double-Publish | Block: Prevent concurrent uploads for the same project |
| **Gate 8** | Platform-Specific Metadata | Block: Title length, tag limits, and description formatting |

## 8. API Error Handling Standards

| HTTP Status | Error Code / Meaning | Scenarios |
|:---:|:---|:---|
| **400** | `INVALID_INPUT` / `MALFORMED_HEADER` | Bad JSON, oversized headers (>256 chars), illegal control chars |
| **401** | `UNAUTHORIZED` | Missing or invalid integration service token |
| **403** | `FORBIDDEN` | Uniform 403 returned on unauthorized or nonexistent project access (oracle elimination) |
| **404** | `NOT_FOUND` | Resource not found on authenticated public endpoints |
| **409** | `CONFLICT` | Optimistic concurrency conflict or illegal state transition |
| **422** | `UNPROCESSABLE_ENTITY` | Certificate requested on non-auditable project |
| **428** | `PRECONDITION_REQUIRED` | Missing required `X-Expected-Version` header |
| **429** | `RATE_LIMIT_EXCEEDED` / `BUDGET_EXCEEDED` | Verification rate limit, BYOK concurrency limit, or token budget ceiling hit |
| **502** | `PROVIDER_FAILURE` | External AI provider error with retry classification |
| **503** | `SERVICE_UNAVAILABLE` | Critical downstream dependency unavailable |

## 9. Version and Change Policy

* Changes to state machines, safety gates, or contract schemas increment the contract version (e.g., `v2` ➔ `v3`).
* All changes must be backed by automated regression tests in `backend/tests/`.
